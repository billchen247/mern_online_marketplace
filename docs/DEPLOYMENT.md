# Deployment (Render + MongoDB Atlas)

`render.yaml` defines two services: `marketplace-api` (Node web service) and `marketplace-web` (static site with an SPA rewrite).

## 1. MongoDB Atlas
1. Create a cluster and a database user.
2. *Network Access*: allow Render's outbound IPs, or `0.0.0.0/0` for a demo (less secure).
3. Copy the connection string, e.g. `mongodb+srv://<user>:<password>@<cluster>/<db>?retryWrites=true&w=majority`. **This goes only into Render's dashboard (and your local, git-ignored `backend/.env`) — never into the repository.**

## 2. Create the Blueprint
Render → *New → Blueprint* → pick this repo. Render reads `render.yaml`.

### API service environment
| Key | Value |
| --- | --- |
| `MONGODB_URI` | your Atlas string (secret, set in dashboard) |
| `JWT_SECRET`, `JWT_REFRESH_SECRET` | generated by the blueprint (≥ 16 chars) |
| `CLIENT_URL` | the static site URL, e.g. `https://marketplace-web.onrender.com` |
| `COOKIE_SAMESITE` / `COOKIE_SECURE` | `none` / `true` (already in the blueprint; required because the SPA and API are on different sites) |
| `CLOUDINARY_*` | optional but recommended — local-disk uploads vanish on redeploy |

The server reads `PORT` from Render and binds `0.0.0.0`. Health check: `GET /health`.

### Static site environment
| Key | Value |
| --- | --- |
| `VITE_API_BASE_URL` | `https://<api-service>.onrender.com/api/v1` — baked in at **build time**, so redeploy after changing it |

The rewrite rule `/* → /index.html` makes deep links such as `/products/123` work on refresh.

## 3. Seed (optional)
The seed script refuses to run with `NODE_ENV=production`. To load demo data into a hosted database, run it **from your laptop** against Atlas (with your IP allow-listed): `NODE_ENV=development npm run seed`. Don't seed a database holding real data.

## 4. Verify
`curl https://<api>.onrender.com/health` → `{"success":true,"status":"ok","db":"connected",…}`; open the static site, sign in as a demo user, add to cart, check out.

## Troubleshooting
- **Login works but the session is lost on refresh** → cookie settings (`COOKIE_SAMESITE=none`, `COOKIE_SECURE=true`) or `CLIENT_URL` mismatch (CORS).
- **API crashes at boot** → production requires `MONGODB_URI` and secrets ≥ 16 chars.
- **Mongo timeouts** → Atlas IP allow-list.
- **First request slow** → free-tier cold start.
